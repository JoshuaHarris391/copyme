# How to refresh the generic-prose baseline

This is the one recurring manual task v2 introduces. It is a maintenance job, not
something a user of the app ever does.

## What the baseline is for

copyme only tells a model to do something if the model would not already do it. A
feature within half a standard deviation of the baseline produces **no rule**, because
the model's default is already right and every extra line dilutes the ones that matter.
The baseline is also what "unlike generic prose" means when a passage is scored for
distinctiveness.

So the baseline is a null hypothesis, and it has to be a sample of what a model writes
unprompted — not a sample of generic *human* prose, which is a different distribution
and would suppress the wrong rules.

`src/copyme/data/baseline.json` holds feature means and spreads only. No text from the
corpus ships in the package.

## Current status: measured

| | |
|---|---|
| Source | Generated responses to plain user questions, no style instruction |
| Model | `claude-sonnet-5` |
| Size | 1,152 passages, 391,398 words |
| Generated by | `scripts/generate_baseline_corpus.py` |
| Spreads inside the 5% stability tolerance | 21 of 36, including every feature driving a substantive rule |

The 15 features whose spreads have not converged are the near-zero-frequency ones —
emoji at 0.11 occurrences per 1,000 words, exclamations at 0.06, ellipses at 0.16,
semicolons at 0.52 — plus `lowercase_start_rate`, which is a near-constant at 0.999.
These are rare events with heavy tails: the spread is set by a handful of outlier
passages, so it is noisy in relative terms however large the corpus gets within reason.

For suppression this is mostly benign in direction. Where the model's mean is near zero
and its spread small, an author who genuinely uses semicolons or exclamations lands many
spreads away and the decision is robust even if the spread is 70% out. The case it is
**not** robust for is an author sitting close to the half-standard-deviation threshold
on one of those features. The per-feature figures are in `baseline.json` under
`stability.unstable_features`, so that can be checked rather than guessed at.

### What the previous corpus got wrong

Worth recording, because it is the reason to prefer measurement over a plausible
substitute. The baseline shipped first as 20 hand-written passages, about 4,000 words,
and on several features it was not merely imprecise but wrong:

- Its passages were **single paragraphs**, so `paragraph_sentences_median` had a large
  false salience for every author profiled against it. The real default is 3.0 sentences
  a paragraph, and most authors sit near it, so the rule now correctly suppresses.
- It **almost never wrote as *I***, so any first-person author scored an implausible
  deviation. Henry James scored 22 standard deviations on a 4,600-word slice.
- It had **no questions, exclamations, ellipses or fragments** to compare against, so
  those rules were suppressed for authors who genuinely use them. Wilde's stage dialogue
  now correctly gets "let one in three sentences be a fragment".

Any rule phrasing tuned against a baseline must be re-checked when it is replaced —
step 5 below.

## When to refresh

- When the corpus is replaced with real model output. This is the one that matters.
- When a feature is added to `FEATURE_NAMES`. A feature with no baseline cannot be
  suppressed or ranked, and `tests/test_baseline.py` fails until the baseline covers it.
- When the model families copyme is mostly pointed at change materially. The risk is
  recorded as medium and slow in [../product/roadmap.md](../product/roadmap.md); a
  yearly check is the current assumption, and the first refresh should test it.

## The procedure

### 1. Generate the corpus

```bash
poetry run python3 scripts/generate_baseline_corpus.py --dry-run --target 1600
poetry run python3 scripts/generate_baseline_corpus.py --target 1600 --concurrency 12
```

The script reads `ANTHROPIC_API_KEY` from the environment itself and never writes it
anywhere. Target a few hundred thousand words; 1,600 calls produced 1,152 passages and
391,398 words, which took about an hour and cost a few dollars of output tokens.

Two things to know before changing the prompts.

**Ask for prose, and do not ask for a style.** The script's question shapes request
paragraphs because copyme's features are prose features — sentence-length quartiles,
paragraph shape, closing sentences — and a bulleted list has no paragraph shape to
measure. Nothing in a prompt says how to write those paragraphs. That line between
format and style is what keeps the register the model's own, and it is easy to cross by
accident.

**Check the prose rate before paying for a full run.**

```bash
poetry run python3 scripts/generate_baseline_corpus.py --probe 2
```

This samples two topics per shape and reports the share of responses that came back as
prose. It exists because the first attempt at this corpus used reference-style questions
and 17 of the first 20 responses were bullet lists; four of the twelve shapes tried
returned prose **never**, and were dropped on that evidence. A shape below about half is
not worth keeping.

### 2. Check the corpus is large enough

```bash
poetry run python3 scripts/build_baseline.py --check
```

This writes nothing. It computes each feature's spread over the first half of the corpus
and over the second half, and reports every feature whose spreads differ by more than
5%, with the mean and spread alongside.

**Read the absolute numbers, not only the percentage.** A feature occurring 0.06 times
per 1,000 words can differ by 34% between halves while moving by almost nothing, and no
realistic corpus size will converge it — the spread is set by a handful of outlier
passages. The question to ask is which features are unconverged, not how many:

- If a feature that **drives a substantive rule** is unconverged — sentence length and
  its variation, paragraph length, contraction rate, conjunction openers, commas,
  fragments, discourse markers, closing sentences — the corpus is genuinely too small.
  Generate more and re-run. `tests/test_baseline.py` enforces this list.
- If only **near-zero-frequency** features are unconverged, that is the expected state
  and the corpus is done. Record which ones; they are written into `baseline.json`
  automatically.

### 3. Remove the old corpus

The generator deletes its own `generated_*.txt` shards on a fresh run, but leaves any
other `*.txt` alone, and `build_baseline.py` globs them all. A leftover file is silently
mixed into the new numbers — this happened on the first run and showed up only as a
passage count 20 higher than the generator reported. Check the count matches before
writing.

### 4. Write it

```bash
poetry run python3 scripts/build_baseline.py --bump
```

`--bump` raises the baseline version. Use it whenever the numbers change materially:
every profile records the baseline version it was built against, so an old profile stays
interpretable rather than looking simply wrong.

### 5. Re-read the rules on the golden samples

A phrasing tuned against one baseline can read as an overclaim against another, and a
rule can appear or vanish because the thing it is measured against moved.

```bash
poetry run python3 -m copyme.cli profile tests/fixtures/london.txt --out /tmp/l.json --memory-gb 3 --quiet
poetry run python3 -m copyme.cli render /tmp/l.json --format rules
```

Compare against the previous baseline rather than reading in isolation —
`git show HEAD:src/copyme/data/baseline.json` gives the old file, and
`load_baseline(path)` takes it, so the two rule sets can be diffed directly. On the last
refresh that diff is what showed `paragraph_sentences_median` correctly disappearing and
contraction rules correctly appearing.

### 6. Run the tests

```bash
poetry run python3 -m pytest -q
```

`tests/test_baseline.py` checks three things: that the baseline is measured from real
model output and records which model, that every feature driving a substantive rule has
converged, and that the unconverged ones are recorded with the numbers needed to judge
them. If the set of substantive features changes, that list is the thing to update.
